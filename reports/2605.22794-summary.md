## Abstract Summary

Autonomous agentic systems (e.g., OpenClaw) remain largely static after deployment. Existing self-evolving agents confine adaptation to text-mutable artifacts — prompts, skills, memory schemas, and workflow graphs — while leaving the agent harness (routing, hooks, dispatch, session lifecycle) untouched. This paper argues that source-level self-rewriting is a fundamentally more general medium: it is Turing-complete, strictly superset to all text-mutable scopes, deterministic in effect, and stable under long-context drift. The authors present **MOSS**, a system that performs source-level self-rewriting on production agentic substrates, anchored to curated production-failure evidence and verified via ephemeral trial workers before promotion through a user-consent-gated container swap.

---

## Key Findings

1. **Scope Gap in Prior Work**: All surveyed self-evolving agent systems (Hermes Agent, SkillClaw, GenericAgent, EvoAgentX) edit only text-mutable artifacts; none modify the harness layer where routing, state management, and dispatch live. This leaves a class of structural failures permanently unreachable.

2. **Source-Level Superiority**: Code-level adaptation is argued to be superior along four axes:
   - **Turing-complete**: can represent any text-mutable configuration and arbitrary structures beyond them.
   - **Strict superset**: every prompt/skill/memory edit has an equivalent code edit; the converse is false.
   - **Deterministic effect**: harness behavior runs as compiled code, not as base-model compliance to rewritten text.
   - **No long-context drift**: source edits are encoded behavior, not text to be re-read on every turn.

3. **Empirical Gain on OpenClaw**: On a four-task claweval benchmark (SLA compliance audit and restock-chain check, in Chinese and English), MOSS lifts the mean grader score from **0.2526 to 0.6100** in a single evolution cycle without human intervention. The largest single gain is +0.6959 (T138 restock-chain check, rising to 0.9049).

4. **Directed vs. Exploratory Evolution**: Unlike academic predecessors that use benchmark-score-driven random mutation, MOSS anchors each evolution to a concrete batch of production-failure evidence. This prevents undirected regression under live traffic and guarantees the fix addresses the specific user-reported scenario.

## Methodology

### System Architecture (Five Components)

1. **Substrate Container**: Runs the user-facing agent (OpenClaw in the case study). Hosts the evolution service and a bind-mounted `moss evo` CLI.
2. **Control Surface**: A CLI (`moss evo`) with nine subcommands (status, batches, batch, start, stop, restart, apply, flag, catch-up) injected into the substrate via system-prompt injection and webhook events.
3. **External Coding-Agent CLI**: Pluggable coding agent (Claude Code, OpenAI Codex, DeepSeek-TUI, OpenCode) invoked per stage as a host-side subprocess. MOSS owns stage ordering and verdicts; the CLI owns the edit.
4. **Host-Daemon**: An asyncio process supervising coding-agent invocation, trial-worker lifecycle, Docker builds, auto-scan engine, and swap-supervision with rollback.
5. **Ephemeral Trial Workers**: Short-lived containers spawned from the candidate image to replay batch tasks autonomously and expose runtime faults.

### Evidence Collection

- **Auto-scan (`moss evo catch-up`)**: Periodic background scan over session JSONLs slices new content into chunks; only weak/missing keypoints are appended to the open batch.
- **User flag (`moss evo flag`)**: User-expressed dissatisfaction triggers the same scan on a single session.
- **Batch threshold**: Open batch seals and is replaced when chunk count reaches 8 (configurable).

### The Seven-Stage Evolution Pipeline

Each iteration runs a deterministic seven-stage pipeline with two review gates:

1. **Locate** — Diagnose the failure from baseline traces and batch failures; no fixes proposed.
2. **Plan** — Identify root cause and specify the fix (files, logic, scope).
3. **Plan-Review** — Quality gate; plan alternates with Plan until approved or round-budget cap.
4. **Implement** — Write the code as a single git commit in the inner substrate repository.
5. **Code-Review** — Second quality gate; diff reviewed against the plan. Working tree hard-resets between rounds.
6. **Task-Evaluate** — After Build and Trial, scores 4–7 keypoints per task on a four-level scale (strong / adequate / weak / missing).
7. **Verdict** — Synthesizes evaluations into one of: `CONVERGED`, `NEED_MORE_WORK`, `FUNDAMENTAL_LIMIT_MODEL`, `FUNDAMENTAL_LIMIT_ARCHITECTURE`. A plateau guard forces convergence if no improvement is seen across a depth-dependent window.

### Runtime Verification

Candidates are verified by spawning N ephemeral trial-worker containers from the candidate image. Each batch task is replayed autonomously across multiple trials to expose flakiness. Trial workers are network- and mount-isolated from the live main container.

### In-Place Container Swap

On `CONVERGED`, the user must explicitly authorize promotion via `moss evo apply`. The host-daemon performs an in-place container swap:
- Restarts the substrate container against the candidate image.
- 90-second probe window (every 5 s) with four health checks.
- Three consecutive passes commit the swap; failure triggers rollback to the last-known-good image.
- User-state volume (sessions, memory, credentials, configs) survives untouched.

---

## Conclusions

MOSS demonstrates that source-level self-rewriting on production agentic substrates is not only feasible but empirically effective. By extending the editable scope from prompts and skills to the harness itself, it closes a structural gap that text-mutable evolution cannot reach. The deterministic, evidence-anchored pipeline — with explicit review gates, runtime trial verification, and user-consent-gated promotion — provides a safe upgrade path for live deployments. The authors position MOSS as the combination of the academic line (source-level feasibility on minimal scaffolds) and the application line (production deployment with text-mutable artifacts), achieving the former on the scale of the latter.
