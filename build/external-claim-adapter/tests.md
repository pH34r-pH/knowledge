# External claim adapter independent test contract

Cases state spec-level behavior. Some adopt the existing adapter tests, which cover duplicate IDs, broken references, supersession, hash binding and the acceptance gate. The new file `tools/test_external_claim_adapter_spec.py` adds cases for the rules those tests do not pin down: loading and confinement, identity patterns, offline levels, local evidence, the edges of the acceptance gate, the command-line contract, the registry identity and offline operation. The new cases were written from the specification after characterization, and a fault-injection spot check confirmed they fail when the behavior they cover is broken. A case passes when every listed test passes.

| Case | Requirements | Stimulus | Expected observable result | Executable tests |
| --- | --- | --- | --- | --- |
| ECA-001 | ECA-FR-001, ECA-SC-001 | Load registries with an absent review file, a missing registry file and a symbolic-link registry. | An absent review file reads as empty; a missing or linked registry file is an input error. | `tools/test_external_claim_adapter_spec.py::test_eca_001_registry_files_are_loaded_from_inside_the_root` |
| ECA-002 | ECA-FR-002, ECA-SC-001 | Load lines that are invalid JSON, not objects, repeat a field, or are blank; load empty registries. | Bad lines are input errors naming file and line; blank lines are skipped; empty registries are valid. | `tools/test_external_claim_adapter_spec.py::test_eca_002_each_line_is_one_strict_json_object`; `tools/test_external_claim_adapter.py::test_empty_registry_is_valid` |
| ECA-003 | ECA-FR-003, ECA-SC-001 | Use malformed IDs, mismatched types, a missing ID and an ID shared across registries. | Each is an error naming the record; each occurrence of a shared ID after the first is reported. | `tools/test_external_claim_adapter_spec.py::test_eca_003_identity_type_and_uniqueness`; `tools/test_external_claim_adapter.py::test_duplicate_adapter_id_fails_closed` |
| ECA-004 | ECA-FR-004, ECA-SC-001 | Reference a missing work from a claim and a missing claim from evidence. | Each broken reference is an error naming the record. | `tools/test_external_claim_adapter.py::test_broken_references_fail_closed` |
| ECA-005 | ECA-FR-005, ECA-SC-001 | Supersede a record validly, across kinds, itself, a missing target and in a cycle. | A valid chain passes and the old record stays valid; the others fail; a cycle is reported once from its smallest ID. | `tools/test_external_claim_adapter_spec.py::test_eca_005_supersession_is_same_kind_and_acyclic`; `tools/test_external_claim_adapter.py::test_self_supersession_fails_for_each_record_type`; `tools/test_external_claim_adapter.py::test_cyclic_supersession_fails_for_each_record_type` |

| ECA-007 | ECA-FR-007, ECA-SC-001 | Point local evidence at valid, missing, escaping, absolute, blank and mismatched files. | Only a regular file inside the root with a matching lowercase hash passes. | `tools/test_external_claim_adapter_spec.py::test_eca_007_local_evidence_is_bound_to_a_file_inside_the_root` |
| ECA-008 | ECA-FR-008, ECA-SC-001 | Accept a claim with passing, archived, failing, absent and non-accepted evidence. | Acceptance needs at least one accepted record with a fully passed audit; a real work or failed entailment never qualifies. | `tools/test_external_claim_adapter_spec.py::test_eca_008_acceptance_needs_one_fully_passed_audit`; `tools/test_external_claim_adapter.py::test_accepted_claim_requires_fully_audited_evidence`; `tools/test_external_claim_adapter.py::test_real_work_identity_does_not_rescue_failed_entailment`; `tools/test_external_claim_adapter.py::test_valid_offline_claim_evidence_passes` |
| ECA-009 | ECA-FR-009, ECA-SC-001 | Give a work its own source review or permitted uses. | The record is rejected; source policy lives only in the governance file. | `tools/test_external_claim_adapter.py::test_work_content_cannot_supply_its_own_review` |
| ECA-010 | ECA-FR-010, ECA-SC-001 | Run the command on valid registries, on registries with several errors and on malformed input. | 0 with the OK line; 1 with every error and the failure count; 2 with an error line. | `tools/test_external_claim_adapter_spec.py::test_eca_010_command_line_result` |

| ECA-012 | ECA-FR-012, ECA-SC-001 | Validate with all network access forbidden. | Validation succeeds without any network call. | `tools/test_external_claim_adapter_spec.py::test_eca_012_validation_makes_no_network_request` |
